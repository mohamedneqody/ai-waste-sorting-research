# README_RUN — دليل سير العمل (نسخة الأدوار المحدثة)

> **تقسيم الأدوار المعتمد (4/10/2026):**
> **الطالبة:** التصوير + وضع كل صورة في فولدر فئتها الصحيح + حسم الحالات غير الواضحة التي يعرضها الوكيل في تقرير واحد.
> **الوكيل (المهندس):** ينفذ **كل** الأوامر التقنية — التوليد، المعاينة، التقييم، المقارنة، تحديث البحث. الطالبة لا تشغّل أي أمر Python.

## المرحلة 0: البيئة (مثبتة على هذا الجهاز — مرجع فقط)
Python 3.14 + torch/torchvision (CUDA — NVIDIA T1200) + scikit-learn + matplotlib + Pillow + Flask ✅

## المرحلة 1 (الطالبة): وضع الصور
```
D:\waste_research\data\local_egypt\
  cardboard\  glass\  metal\  paper\  plastic\  trash\
```
- الحد الأدنى: 100 صورة و10 لكل فئة (المستهدف 150 — 25 لكل فئة). القواعد الكاملة: [docs/image_collection_protocol.md](docs/image_collection_protocol.md)
- الصور تُجمد بعد التجميع — لا حذف ولا استبدال بعد بدء التقييم.

## المرحلة 2 (الوكيل): توليد البيان
`python scripts/make_manifest.py` → يولّد `eg_waste_manifest.csv` بالأعمدة: image_id، image_path، true_label (من الفولدرات فعليًا).

## المرحلة 3 (الوكيل ثم الطالبة): المعاينة البصرية والحكم
1. `python scripts/contact_sheet.py` → أوراق معاينة `review/contact_sheet_XX.png` (مصغرات كل الصور مع هويتها).
2. الوكيل يفحص الأوراق بصريًا ويملأ في `review/contact_sheet_decisions.csv` لكل صورة:
   - `scene_type`: **single** (عنصر واحد مسيطر ~2/3 الكادر بخلفية بسيطة) أو **crowded** (مشهد مزدحم متداخل)
   - `difficulty`: **normal** أو **transparent_hard** (الشفاف الشبيه بالفئة الأخرى: بلاستيك↔زجاج)
   - `unclear`: **yes** إذا لم يستطع الحسم بثقة (مع قيمة مقترحة)
3. `python scripts/contact_sheet.py apply` → يدمج القرارات في البيان + يولّد **`review/unclear_report.md`** (تقرير واحد فقط بالصور غير الواضحة وحكم مقترح).
4. **الطالبة تحسم** كل حالة في التقرير (تأكيد أو تعديل) → الوكيل يعدّل القرارات ويعيد apply مرة أخيرة.
- التقييم لن يبدأ إلا إذا كان كل صورة لها scene_type/difficulty صحيح والبيان مطابق للفولدرات تمامًا.

## المرحلة 4 (الوكيل): تقييم MobileNetV2 (RQ1)
`python scripts/evaluate_mobilenet.py`
- بوابة ثلاثية: كفاية الصور (≥100 و≥10/فئة) + **صلاحية البيان الكاملة** + **فحص قابلية قراءة كل صورة مسبقًا** — وأي فشل أثناء الاستدلال يوقف كل شيء قبل كتابة أي ملف. **لا تقييم جزئي إطلاقًا ولا تُنشأ results في حالة الفشل.**
- المخرجات في `results/`: `predictions_mobilenet.csv` (لكل صورة: المسار، الحقيقي، المتوقع، الثقة، الزمن، الجهاز، نوع المشهد، الصعوبة) + `classification_report_mobilenet.csv` + `confusion_matrix_mobilenet.png` + `summary_mobilenet.json` (دقة/ماكرو F1/تعريف الزمن/الجهاز/الإصدارات/تاريخ التشغيل).
- ⚠️ دقة هذا الاختبار **خارجية محلية** — لا تُخلط بدقة 89.21% الداخلية على TrashNet.

## المرحلة 5 (الطالبة ثم الوكيل): Gemini ثم المقارنة (RQ2)
- **الطالبة فقط:** تجهز مفتاحًا مجانيًا من https://aistudio.google.com/apikey وتضبطه في PowerShell: `setx GEMINI_API_KEY "..."` ثم طرفية جديدة (لا يُكتب المفتاح في أي ملف).
- **الوكيل:** `python scripts/evaluate_gemini.py` — مطالبة ثابتة، مطابقة كاملة للفئة (بلا بحث جزئي)، MIME حقيقي، **قاعدة الاكتمال: أي صورة فاشلة أو إجابة غير قابلة للتحليل = التجربة غير مكتملة ولا تُحسب مقاييس جزئية**.
- **سياسة إعادة المحاولة:** الأخطاء التقنية فقط (شبكة / 429 / 5xx) تُعاد تلقائيًا بنفس الطلب والمطالبة نفسها حتى 3 محاولات، مع تسجيل عدد المحاولات وسبب كل فشل. الطلب الناجح لا يُعاد أبدًا بسبب نتيجته، والإجابة غير القابلة للتحليل لا تُعاد، وأخطاء HTTP الدائمة (400/401/403…) فشل نهائي. الصور المعلقة تقنيًا تُستكمل في تشغيل لاحق (checkpoint أحداث) — والنجاحات لا تُعاد.
- **الوكيل:** `python scripts/compare_models.py` — يرفض المقارنة إلا إذا كل صور البيان موجودة في الملفين بتسمية مطابقة (لا مقارنة جزئية إطلاقًا). المخرجات: `comparison_table.csv/md` + مصفوفتا مقارنة + رسم F1.
